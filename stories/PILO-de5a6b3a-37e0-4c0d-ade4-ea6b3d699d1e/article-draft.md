---
title: The project manager was already there
date: 'Wednesday, September 30, 2026'
description: Two new coding projects arrived with a management system their
  developers had never chosen.
standfirst: An instruction installed beside an AI coding agent became a quiet
  standing order. New projects inherited it before their people knew to object.
---

Two developers opened new coding projects and found that a project manager had
already moved in.

The manager was Kanbus, a tool for keeping project work on a board. Neither
developer had chosen it for the new project. Yet there it was: set up among the
fresh files, ready to turn work into tasks and tasks into a routine.

The explanation sat outside both projects.

For a time, installing Kanbus also placed a skill beside the user’s coding
agent, at the user level rather than inside any one project. It was meant to
be helpful. The skill explained how to use Kanbus for project management and
strongly recommended that it be used when work began.

An AI coding agent does not experience that kind of document as casual advice.
It reads standing instructions as part of the job. When each developer asked
an agent to make a new project, the agent met the old Kanbus instruction before
it met the new project’s own preferences. It followed the instruction and set
up Kanbus.

The developers noticed after the arrival, when the fresh projects contained a
system neither had selected. They had asked for a new place to work; a small
administration had come with the keys.

Nothing dramatic had crossed the screen. There was no stranger’s command in a
pop-up, no password stolen, no red warning about an intruder. A recommendation
had found a durable place to live. From there it could enter every new project
as the sensible way things were done.

That is the peculiar new life of an instruction file. It can begin as a note
for one person’s assistant, then become a little piece of policy when an agent
treats it as a permanent rule. In these two projects, the policy arrived before
the developers had been asked for it.

Kanbus did not mean to spread this way. The effect came from placing an
opinionated skill above the project boundary, where each newborn project could
inherit it without a vote. The agents were behaving exactly as they had been
taught to behave: carrying forward the instructions already around them.

A project used to begin as an empty folder. Now it can wake up with a workflow,
a board, and a belief about how work must be organized—before anyone has had
the chance to decide whether it belongs there.
